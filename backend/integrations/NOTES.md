## Export design decisions

1. **Plan DAG extraction.** The exporter scans `run_snapshot["events"]` for
   `plan_created` envelopes and picks the one with the highest `seq` (re-plans
   win deterministically). `payload.subtasks` is validated: ids deduplicated
   (`_dup2` suffix on collision), titles collapsed/truncated (48 chars), agents
   defaulted to `analyst` when missing, and `depends_on` filtered to known ids
   (dangling deps dropped, self-deps dropped). Degradable problems never raise —
   they fall back and the reason lands in `meta.plan_note`.
2. **Topological layout.** Kahn's algorithm with a min-heap on original index →
   deterministic node order; depth = longest path from a root; layers are
   staggered vertically (`±110px` per slot) so parallel branches fan out on the
   canvas; each subtask layer spans a Set node + HTTP Request node (220px apart).
3. **Node chain per subtask** (mirrors the run plan):
   - `>= 2` deps → **NoOp join point** first (all dep HTTP nodes feed it) — this
     is what the brief's "NoOp (join points)" is for; single-dep and root steps
     wire directly.
   - **Set "Context [agent]: title"** assembles the step context: static plan
     fields (subtask_id/title/agent/depends_on) baked at export time; run/mission
     fields + `api_url` pulled from the Mission Context node via
     `$('Mission Context').first().json...` expressions; `upstream_outputs` (array)
     from `$input.all()`.
   - **HTTP Request "Run Step [agent]: title"** POSTs the full context
     (`jsonBody: ={{ $json }}`) with `X-AgentForge-Subtask` / `X-AgentForge-Agent`
     headers.
4. **Critic verdict branch.** The deepest `critic`-agent step feeds an **IF**
   node (`approved !== false` → pass). True → **Code "Assemble Report"** →
   **HTTP Request "Deliver Report"**. False → **NoOp "Flagged for Rework"** (the
   documented extension point where a retry/human-review path plugs in). With no
   critic step, terminal steps converge through a "Join: Report Inputs" NoOp on
   the assembler. The Code node references *every* step node by name, so the
   report assembles the full plan even though only the critic branch flows in.
5. **Determinism (test-pinned).** Node ids and webhook ids are `uuid5` over
   `"{run_id}|{node_name}"` under a fixed namespace; positions are computed from
   the DAG; `meta` carries **no wall-clock timestamp**. Same snapshot in →
   byte-identical JSON out. The committed examples are regenerated by
   `make_examples.py` and verified reproducible.
6. **Mission values as n8n fallbacks.** The Mission Context Set node prefers the
   webhook body (`$json.body.goal` etc.) and falls back to the exported run's
   mission values, JS-escaped via `_js_quote`. Re-driving the workflow for a new
   goal = POST a different body to the webhook; the exported DAG stays.

## Node-type choices (core only, realistic typeVersions)

| Type | n8n type string | typeVersion | Why |
|---|---|---|---|
| Webhook | `n8n-nodes-base.webhook` | 2 | trigger; path `agentforge-run-{run_id}`; `responseMode: onReceived` so the trigger acks immediately |
| HTTP Request | `n8n-nodes-base.httpRequest` | 4.2 | one per subtask + the report delivery node; JSON body + custom headers |
| Set | `n8n-nodes-base.set` | 3.4 | `assignments` array form (current Set v3 shape) for context assembly |
| Code | `n8n-nodes-base.code` | 2 | `runOnceForAllItems` report assembly; ES5-style JS for wide n8n compatibility |
| IF | `n8n-nodes-base.if` | 2.2 | v2 conditions structure (single boolean condition, `typeValidation: loose`) |
| NoOp | `n8n-nodes-base.noOp` | 1 | join points / flagged-for-rework placeholder |

Workflow-level: `"settings": {"executionOrder": "v1"}` is emitted (see
DEVIATIONS) so multi-branch DAG execution order is correct on import.

## URL honesty statement

Every HTTP node URL is an n8n expression rooted at
`{{ $env.AGENTFORGE_API_URL || 'http://agentforge-backend:8000' }}` (stored in
Mission Context as `api_url`). There are **no third-party APIs, no credentials,
no fabricated integrations** anywhere in the export. Paths:

- Steps: `POST {base}/api/runs/{run_id}/steps/{subtask_id}` — the export's
  re-drive convention for executing one plan subtask with its context. The
  pinned v1 backend exposes run-level endpoints only, so executing the scaffold
  step-by-step against a stock backend expects a thin step-endpoint shim (or
  repoint the URLs at your own workers inside n8n). The DAG wiring, critic
  branch, and report delivery are real; the per-step path is a documented
  convention, not a hidden fake.
- Report: `POST {base}/api/runs/{run_id}/report` — delivers the assembled
  report to the AgentForge backend. The pinned v1 API *serves* reports at
  `GET /api/runs/{id}/report`; flip the node's method to GET to fetch the
  rendered report instead of POSTing one.

n8n edition caveat (documented in the README too): `$env` works on self-hosted
n8n; **n8n Cloud blocks `$env` access in expressions**, so Cloud users replace
`$env.AGENTFORGE_API_URL` with their literal URL (or an n8n Variable via
`$vars`). The expressions fall back to the default host otherwise.

## DEVIATIONS

- **`settings` key added** to the output (`{"executionOrder": "v1"}`). The brief
  pins `{"name", "nodes", "connections", "meta"}`; `settings` is standard n8n
  workflow JSON and required for correct multi-branch execution order on import.
  INTERFACES.md's minimal `{"name", "nodes", "connections"}` still holds; extra
  keys are accepted by n8n import.
- **NoOp joins inserted for fan-in** (when a subtask has ≥ 2 dependencies) rather
  than wiring N edges directly into one node — keeps n8n execution order sane and
  gives the DAG a visible join point on the canvas.
- **Fallback linear pipeline is planner → analyst → critic → report** exactly as
  the brief pins it (no researcher/forecaster steps in the fallback, since
  without a real plan their subtasks are unknowable).
- **`meta.plan_note`** added alongside the pinned fields to record *why* a
  fallback happened (no plan event / invalid subtasks / cycle) — used by tests
  and useful for debugging exports.
- Per-step POST path follows a `steps/{subtask_id}` convention that the stock v1
  backend does not implement (see URL honesty above); documented rather than
  faked. No other deviations from docs/SPEC.md or docs/INTERFACES.md.
